AI 人物媒体一键标记工具 v1.0.0（便携 EXE 版）
==========================================

一、怎么使用

1. 先由人工判断哪些图片、视频确实适用该披露标签，再把它们放入
   “待标记”文件夹。
   可以继续建立子文件夹，工具会递归扫描。
2. 双击“AI人物媒体标记工具.exe”。
3. 扫描完成后，根据需要点击：

   - “开始标记”：为未合规文件写入标签，并在写入后严格验证。
   - “只读验证”：只检查当前合规状态，不修改任何媒体文件。

4. 等待任务完成。界面会显示结果和验证证据。
5. 点击“查看运行记录”可打开本次 CSV 明细。

本版本已经包含 Python 运行环境，使用者无需安装 Python，也无需另外
安装 ExifTool。

重要：本工具不会识别或判断媒体是否包含 AI 生成人物。“开始标记”会
为“待标记”中所有尚未合规的支持文件添加标签。请勿放入不适用该标签
的媒体。

二、支持的文件

- JPG / JPEG
- PNG
- MP4

扩展名不区分大小写。其他格式不会被处理。

三、两种运行模式

【开始标记】

- 直接修改“待标记”中的原文件，不生成备份或 *_original 文件。
- 建议先保留一份原始素材副本，再放入“待标记”。
- 已严格合规的文件不会重复写入。
- 缺少目标关键词的文件会追加关键词，并保留其他 Subject 关键词。
- 写入后立即重新读取字段和原始 XMP；严格验证通过才显示“新增”。
- 对于需要写入的只读、隐藏、系统文件或符号链接，会跳过并记录失败。

【只读验证】

- 不写入媒体，不改变标签；只会在“运行记录”中生成 CSV。
- 可以检查只读、隐藏、系统属性的普通媒体文件。
- 适合交付前复查，也适合让使用者确认 MP4 的真实 XMP 状态。
- 结果分为“验证通过 / 未标记 / 验证失败”。

任务进行时请等待窗口完成，不要强行结束程序。

四、严格验证标准

合规必须同时满足：

1. ExifTool 从 XMP-dc:Subject 读取到精确值：

   contains-synthetic-performer

2. 原始 XMP 中确认存在：

   dc:subject → rdf:Bag → rdf:li

3. 该 rdf:li 的值与关键词完全一致。

只有 Microsoft:Category、大小写不同、部分匹配，或字段有值但原始
XMP 不是上述 Bag/li 结构，都不会被判为合规。

工具不会写入 Microsoft:Category。

五、如何看结果

界面明细会逐个显示：

- 文件状态
- 验证字段 XMP-dc:Subject 的实际读取值
- 是否确认 rdf:Bag/rdf:li 结构
- 失败原因（如有）

“验证通过”表示字段和值、原始 XMP 结构都已经由 ExifTool 回读确认，
不是仅凭 Windows 属性页判断。

六、关于 MP4 的 Windows 显示

MP4 正确写入 XMP-dc:Subject 后，Windows“属性 → 详细信息 → 标记”
仍可能显示为空。这是 Windows 资源管理器的显示限制，不代表标签失败。

可随时点击“只读验证”。只要本工具显示“验证通过”，即代表：

- XMP-dc:Subject 中存在精确关键词；
- 原始 XMP 中存在要求的 rdf:Bag/rdf:li；
- CSV 中留有字段值、结构、时间和 ExifTool 版本作为验证记录。

七、运行记录

每次“开始标记”或“只读验证”都会在“运行记录”文件夹生成 UTF-8 CSV，
可直接用 Excel 打开。记录包含：

- 相对路径
- 格式
- 运行模式
- 处理状态
- 验证结果
- 验证字段
- 实际读取值
- XMP 结构
- 验证时间
- ExifTool 版本
- 错误原因

八、运行环境与文件结构

- 面向 Windows 64 位系统。
- 使用者无需安装 Python，也无需另外安装 ExifTool。
- 请不要单独移动 EXE；整个解压出的
  “ai-media-synthetic-marker-v1.0.0”文件夹应一起移动或复制。
- 请保持 EXE、“待标记”“运行记录”和“exiftool”位于同一目录。

- 工具不会上传亚马逊。
- 工具不验证上传后平台是否继续保留元数据。
- 工具与 Amazon 无隶属、合作或官方认可关系。
- “验证通过”不构成法律意见或平台最终审核保证。
- 当前 EXE 未进行代码签名，Windows SmartScreen 可能要求二次确认。
